# NILO Backend — Especificación API (Frontend)

## 1. Concepto clave (léelo primero)

El **clínico da de alta pacientes con `POST /users`** (`type_user: "patient"`).

Ese registro es:
- El **paciente monitorizado** (sujeto pasivo; se graban datos sobre él).
- Una **cuenta de acceso** que en el futuro podrá usar un familiar para loguearse.
- Donde vive la **foto**, el **tipo** (`neonate`/`child`/`adult`), `monitoring_active`, etc.

El dashboard debe listar y gestionar pacientes con **`/users`**, filtrando
`type_user=patient`.

> `/patients` existe solo como registro clínico interno (vídeo, vitales…). Se
> crea/actualiza **automáticamente** al dar de alta o editar un usuario paciente.
> **El frontend no debe usar `POST /patients` para el alta.**

---

## 2. Información general

- **Base URL**: `http://localhost:8001/api/v1`
- **Auth**: `Authorization: Bearer <access_token>` (salvo login/refresh)
- **Login**: `application/x-www-form-urlencoded` (no JSON)
- **Swagger**: `http://localhost:8001/docs`

### Roles

| Rol | Valor | Uso |
|-----|-------|-----|
| Admin | `root` | Gestiona todo |
| Clínico | `clinician` | Da de alta pacientes (`POST /users`) |
| Paciente | `patient` | Cuenta del sujeto monitorizado (login futuro) |

---

## 3. Autenticación

### Login — `POST /auth/login`

Form-urlencoded: `username` = email, `password` = contraseña.

```js
const body = new URLSearchParams({ username: email, password });
const { access_token, refresh_token } = await (
  await fetch(`${BASE}/auth/login`, { method: "POST", body })
).json();
```

### Tokens

- `access_token` → memoria (60 min)
- `refresh_token` → almacenamiento persistente (30 días)

### Refresh — `POST /auth/refresh`

```json
{ "refresh_token": "eyJ..." }
```

Devuelve nuevo par de tokens. Si falla → logout.

### Usuario actual — `GET /auth/me`

## 4. Pacientes — `POST /users` (API principal del dashboard)

### 4.1 Crear paciente (ALTA)

`POST /users` — clínico o root — JSON:

```json
{
  "name": "Pablo",
  "lastname": "Paciente",
  "type_user": "patient",
  "email": "familia@ejemplo.com",
  "password": "secreto",
  "birthdate": "2020-03-15",
  "photo": "data:image/jpeg;base64,/9j/4AAQ...",
  "address": "C/ Ejemplo 1",
  "zip": "28001",
  "country": "ES",
  "phone": "+34600111222",
  "patient_profile": {
    "type_patient": "neonate",
    "monitoring_active": true,
    "medical_record_number": "MRN-00123",
    "sex": "male",
    "room": "UCI",
    "bed": "3",
    "notes": "Neonato en incubadora",
    "relative_name": "María García",
    "relative_contact": "+34600999888",
    "relative_address": "C/ Familiar 1"
  }
}
```

**Campos obligatorios:** `name`, `lastname`, `type_user`, `email`, `password`.

**Importante — `patient_profile` va ANIDADO**, no en la raíz:

| Campo dentro de `patient_profile` | Tipo | Valores |
|-----------------------------------|------|---------|
| `type_patient` | string | `adult` \| `child` \| `neonate` \| `other` |
| `monitoring_active` | bool | Si se recogen datos ahora |
| `medical_record_number` | string | Nº historia (único) |
| `sex` | string | `male` \| `female` \| `other` \| `unknown` |
| `room`, `bed`, `notes` | string | Ubicación / notas |
| `relative_name`, `relative_contact`, `relative_address` | string | Contacto familiar |

**Foto:** campo `photo` en la **raíz** (data URI base64) o subir después con
`POST /users/{id}/photo`.

```js
function fileToDataURL(file) {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = () => resolve(reader.result);
    reader.onerror = reject;
    reader.readAsDataURL(file);
  });
}

const photo = await fileToDataURL(fileInput.files[0]);
await fetch(`${BASE}/users`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${token}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    name: "Pablo",
    lastname: "Paciente",
    type_user: "patient",
    email: "familia@ejemplo.com",
    password: "secreto",
    birthdate: "2020-03-15",
    photo,
    patient_profile: {
      type_patient: "neonate",
      monitoring_active: true,
      room: "UCI",
      bed: "3",
    },
  }),
});
```

### 4.2 Listar pacientes del dashboard

`GET /users?type_user=patient`

- **Clínico**: devuelve solo pacientes que él registró.
- **Root**: todos (filtrar con `type_user=patient`).

```js
const patients = await (
  await fetch(`${BASE}/users?type_user=patient`, {
    headers: { Authorization: `Bearer ${token}` },
  })
).json();
```

### 4.3 Obtener un paciente

`GET /users/{user_id}`

### 4.4 Actualizar paciente

`PATCH /users/{user_id}` — JSON parcial.

**Atención:** si envías `patient_profile`, envía el **objeto completo** (se
reemplaza entero):

```json
{
  "patient_profile": {
    "type_patient": "child",
    "monitoring_active": false,
    "room": "301",
    "bed": "2"
  }
}
```

Campos de la raíz (`name`, `photo`, `phone`…) sí son parciales.

### 4.5 Subir foto (multipart)

`POST /users/{user_id}/photo` — form-data, campo `file`.

```js
const fd = new FormData();
fd.append("file", file);
await fetch(`${BASE}/users/${id}/photo`, {
  method: "POST",
  headers: { Authorization: `Bearer ${token}` },
  body: fd,
});
```

### 4.6 Ver la foto

`GET /users/{id}` → campo `photo` (data URI) → `<img src={user.photo} />`

### 4.7 Eliminar paciente

`DELETE /users/{user_id}` — clínico (sus pacientes) o root.

### 4.8 Asignar nodo a un paciente

`PATCH /users/{user_id}/node` — clínico (sus pacientes) o root.

```json
{ "node_id": "6a4bca11d59665843e63485b" }
```

Para desasignar: `{ "node_id": null }`.

El `node_id` debe existir en `/nodes`. Queda guardado en
`patient_profile.node_id` y se devuelve en `GET /users/{id}`.

### 4.9 Pacientes con monitorización activa (resumen)

`GET /users/monitoring-active` — clínico: solo los suyos con
`monitoring_active: true`. Root: todos.

Respuesta ligera:

```json
[
  {
    "id": "6a4bca11...",
    "name": "Pablo",
    "lastname": "Paciente",
    "photo": "data:image/jpeg;base64,..."
  }
]
```

## 5. Nodos — `/nodes`

| Método | Ruta | Auth | Descripción |
|--------|------|------|-------------|
| GET | `/nodes` | Bearer | Listar |
| GET | `/nodes/{id}` | Bearer | Obtener |
| POST | `/nodes` | Staff | Crear |
| PATCH | `/nodes/{id}` | Staff | Actualizar |
| DELETE | `/nodes/{id}` | Staff | Eliminar |

Campos obligatorios al crear: `name`, `mac_address` (única).

---

## 6. Resumen

| Acción | Endpoint |
|--------|----------|
| Login | `POST /auth/login` |
| Refresh | `POST /auth/refresh` |
| **Alta paciente** | **`POST /users`** con `type_user: "patient"` |
| **Listar pacientes** | **`GET /users?type_user=patient`** |
| **Editar paciente** | **`PATCH /users/{id}`** |
| **Foto paciente** | **`POST /users/{id}/photo`** o `photo` en JSON |
| **Asignar nodo** | **`PATCH /users/{id}/node`** con `{ "node_id": "..." }` |
| **Monitorización activa** | **`GET /users/monitoring-active`** |
| **Eliminar paciente** | **`DELETE /users/{id}`** |
| Nodos | `/nodes` |

---

## 7. Errores comunes del frontend

| Error | Causa |
|-------|-------|
| `type_patient` siempre `adult` | Mandaste `type_patient` en la raíz en vez de dentro de `patient_profile` |
| No hay campo `photo` | No enviaste `photo` ni llamaste a `/users/{id}/photo` |
| Login 422 | Enviaste JSON en vez de form-urlencoded |
| 403 al crear paciente | El token no es de un clínico/root |
