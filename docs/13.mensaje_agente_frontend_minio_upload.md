## 1. Cambiar `landmarks.service.ts`

**Objetivo:** `uploadJsonBatch` → **solo** `POST /landmarks/upload` con `FormData` (sin `putPresignedObject`).

Campos form (mismos que `LandmarksUploadRequest`):

- Obligatorios: `session_id`, `patient_id`, `start_ts`, `source`
- Opcionales: `node_id`, `video_segment_id`, `model_name`, `end_ts`, `frame_count`, `file_extension` (default `json`)
- Archivo: `file` = JSON **o gzip** (recomendado MediaPipe 1–2 min, ~478 puntos/frame):
  - `schema: nilo-mediapipe-face-capture-v1`, `landmark_encoding: flat-xyz`
  - Opción A: `Blob` JSON `application/json`
  - Opción B: comprimir con `CompressionStream('gzip')`, adjuntar como `landmarks.json.gz` (`application/gzip`); el backend descomprime y guarda `.json` en MinIO

**413 Request Entity Too Large:** suele ser **nginx** `client_max_body_size` (subir a `64m` en `location ^~ /api/`). Ver `docs/14.nginx_api_upload_limits.md`.

Respuesta: `LandmarksOut` (`id`, `object_key`, `status` = `processed`, `size_bytes`) — **no** hay `upload_url` ni `confirm`.

Opcional: mantener `requestUpload` + `confirm` para herramientas / nilo-node; **no** usarlos desde `uploadJsonBatch` en doctor web.

**Prueba sin UI:**

```bash

  -H "Authorization: Bearer $TOKEN" \
  -F "session_id=..." \
```

## 2. Arreglo en `api.ts` (importante)

En `request()`, **no** añadir `Content-Type: application/json` cuando `body` es **`FormData`** (el navegador debe poner `multipart/form-data` + boundary).

```typescript
const isUrlEncoded = init.body instanceof URLSearchParams
const isMultipart = init.body instanceof FormData
if (init.body != null && !isUrlEncoded && !isMultipart && !headers.has('Content-Type')) {
  headers.set('Content-Type', 'application/json')
}
```

Sin esto, `/landmarks/upload` puede fallar con 422.

## 4. Revisión clínica (datos de hace meses)

Al abrir una sesión en condata / historial:

```http
GET /api/v1/sessions/{sessionId}/media-access?expires_in=86400
Authorization: Bearer …
```

Respuesta: `items[]` con `{ kind, id, download_url, expires_in }`.

- Cachear en memoria de la vista de sesión (no `localStorage` de URLs).
- Al reentrar en la ficha o pasado `expires_in`, volver a llamar.
- Reproducir audio: usar `download_url` de `items` donde `kind === 'audio'` o seguir con `GET /audio/{id}/download` (TTL 24 h en backend).

Los objetos **no caducan** en MinIO; solo las URLs presignadas.
