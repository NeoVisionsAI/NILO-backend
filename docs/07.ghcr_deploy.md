# Imagen Docker en GHCR (build, push y pull)

La **API** se publica como imagen en **GitHub Container Registry**:

```text
ghcr.io/neovisionsai/nilo-backend:<tag>
```

(`neovisionsai` en minúsculas; coincide con la org/usuario de GitHub `NeoVisionsAI`.)

MongoDB y MinIO **no** van en esa imagen: en el servidor destino siguen con `docker-compose.yml` (contenedores `mongo` y `minio`) o infra externa vía `NILO_INFRA_HOST`.

---

## 1. Publicar (CI automático)

Al hacer **push** a `main` o `master`, el workflow [`.github/workflows/publish-ghcr.yml`](../.github/workflows/publish-ghcr.yml) construye y sube la imagen.

Tags típicos:

| Tag | Cuándo |
|-----|--------|
| `latest` | último commit en la rama por defecto |
| `main` (o nombre de rama) | push a esa rama |
| `<sha>` | commit concreto |
| `v1.0.0` | push de tag git `v*` |

También puedes lanzarlo a mano: **Actions → Publish API image (GHCR) → Run workflow**.

Requisitos en GitHub:

- Repo en GitHub con permisos de **Packages** para Actions (el `GITHUB_TOKEN` del workflow ya lleva `packages: write`).
- Primera vez: en **Packages** del repo/org, revisa visibilidad (public/private).

---

## 2. Build y push manual (sin CI)

Desde la raíz del repo:

```bash
export REGISTRY=ghcr.io
export IMAGE=ghcr.io/neovisionsai/nilo-backend
export TAG=latest   # o $(git rev-parse --short HEAD)

echo "$GITHUB_TOKEN" | docker login ghcr.io -u TU_USUARIO_GITHUB --password-stdin

docker build -t "$IMAGE:$TAG" -t "$IMAGE:latest" .
docker push "$IMAGE:$TAG"
docker push "$IMAGE:latest"
```

`GITHUB_TOKEN` o un **PAT** con scope `write:packages` (y `read:packages` si hace falta).

## 3. Desplegar en otro servidor (pull)

### 3.1 Ficheros necesarios en el host

Copia o clona al menos:

- `docker-compose.yml`
- `docker-compose.ghcr.yml`
- `credentials.env` (secretos; **no** va en la imagen)
- `config.yaml` (opcional si solo usas variables de entorno; la imagen ya incluye un `config.yaml` base)

### 3.2 Login en GHCR

Si el paquete es **privado**:

```bash
echo "$GITHUB_TOKEN" | docker login ghcr.io -u TU_USUARIO_GITHUB --password-stdin
```

PAT con `read:packages`.

### 3.3 Arrancar stack con imagen remota

```bash
export NILO_API_IMAGE=ghcr.io/neovisionsai/nilo-backend:latest

docker compose --env-file credentials.env \
  -f docker-compose.yml \
  -f docker-compose.ghcr.yml \
  pull api

docker compose --env-file credentials.env \
  -f docker-compose.yml \
  -f docker-compose.ghcr.yml \
  up -d
```

Solo actualizar la API tras un push nuevo:

```bash
docker compose --env-file credentials.env \
  -f docker-compose.yml \
  -f docker-compose.ghcr.yml \
  pull api

docker compose --env-file credentials.env \
  -f docker-compose.yml \
  -f docker-compose.ghcr.yml \
  up -d api
```

### 3.4 Con `deploy.sh` en el servidor destino

`deploy.sh` sigue haciendo **build local** por defecto. Para usar GHCR:

```bash
export NILO_API_IMAGE=ghcr.io/neovisionsai/nilo-backend:latest
export COMPOSE_FILE="$PWD/docker-compose.yml"
export COMPOSE_OVERRIDE="-f docker-compose.ghcr.yml"

docker compose --env-file credentials.env \
  -f docker-compose.yml -f docker-compose.ghcr.yml \
  pull api

docker compose --env-file credentials.env \
  -f docker-compose.yml -f docker-compose.ghcr.yml \
  up -d --no-build
```

(O integrar en un futuro `./deploy.sh --pull` si lo necesitáis.)

### 3.5 API en VM, Mongo/MinIO en otro host

Usa `docker-compose.api-only.yml` + imagen GHCR (sustituye `build` por `image` igual que en `docker-compose.ghcr.yml`) y `NILO_INFRA_HOST` apuntando al host de datos.

---

## 4. Qué lleva la imagen

- Python 3.13, dependencias, `app/`, `config.yaml`, `scripts/` (backups).
- **No** incluye: `credentials.env`, volúmenes Mongo/MinIO, certificados Caddy.

Secretos siempre en el servidor destino vía `credentials.env` / variables de entorno.

---

## 5. Solución de problemas

| Problema | Qué hacer |
|----------|-----------|
| `denied` al pull | `docker login ghcr.io`; PAT con `read:packages`; permiso al paquete en GitHub |
| Workflow no publica | Actions habilitadas; push a `main`/`master`; revisar log del job |
| API antigua tras pull | Comprobar tag (`:latest` vs sha); `docker compose pull api` sin caché: `docker pull ...` |
| Config distinta en destino | Montar `config.yaml` como volumen o usar env (`NILO_CONFIG_FILE`) |
