# NILO Node - Especificacion de ingestión al backend

Documento para integrar nilo-node (PC de captura) con el backend NILO.

Base URL de ejemplo: http://192.168.1.43:8001/api/v1
HTTPS (si esta activo): https://192.168.1.43:8443/api/v1

Todos los timestamps en UTC, formato ISO-8601: 2026-09-17T10:30:00Z

El patient_id es el ID del paciente CLINICO (coleccion /patients), NO el User del portal.


================================================================================
CONFIGURACION DE NILO-NODE
================================================================================

Variables de entorno sugeridas:

  NILO_API_BASE=http://192.168.1.43:8001/api/v1
  NILO_MINIO_PUBLIC=192.168.1.43:9002
  NILO_EMAIL=clinician@niloai.net
  NILO_PASSWORD=clinician
  NILO_NODE_ID=<ObjectId del nodo registrado en el backend>

Opcional para tests con patient_id fijo:

  NILO_PATIENT_ID=<ObjectId del Patient clinico>


Credenciales demo (SEED_USERS=true en config.yaml):

  Clinico (usar en nilo-node):
    email: clinician@niloai.net
    password: clinician

  Root (solo admin):
    email: root@niloai.net
    password: root

  Paciente portal (NO usar en nilo-node):
    email: patient@niloai.net
    password: patient

IMPORTANTE: no hay rol "node" ni API key propia. nilo-node debe autenticarse
como clinician (o root). Todas las operaciones de volcado requieren rol staff.


================================================================================
AUTENTICACION
================================================================================

Login:

  POST /api/v1/auth/login
  Content-Type: application/x-www-form-urlencoded

  Body:
    username=clinician@niloai.net&password=clinician

  Respuesta JSON:
    access_token
    refresh_token
    token_type (bearer)

Peticiones siguientes:

  Header: Authorization: Bearer <access_token>

El access_token dura 60 minutos. Para sesiones largas o indefinidas, renovar:

  POST /api/v1/auth/refresh
  Content-Type: application/json

  Body:
    {"refresh_token": "..."}


================================================================================
FLUJO DE ARRANQUE
================================================================================

  1. POST /auth/login
  2. GET /patients?node_id={NILO_NODE_ID}&active_only=true
     - 1 paciente: usar su id como patient_id
     - 0 pacientes: error (asignar paciente al nodo desde el frontend)
     - mas de 1: error de configuracion
  3. POST /recordings  (crear sesion)
  4. Bucle de captura (X segundos en test, N o indefinido en produccion):
     - video: segments + presigned PUT + confirm
     - landmarks: presigned PUT + confirm
     - audio: presigned PUT + confirm
     - vitales: POST JSON directo
     - pain events (opcional): presigned PUT + confirm
  5. POST /recordings/{recording_id}/end


================================================================================
RESOLVER PACIENTE ASIGNADO AL NODO
================================================================================

  GET /api/v1/patients?node_id={NILO_NODE_ID}
  Authorization: Bearer ...

  Usar el campo "id" del paciente devuelto como patient_id en todos los endpoints.


================================================================================
SESION DE VIDEO (Recording)
================================================================================

La sesion de monitorizacion es un Recording.

  - ID interno: recording.id (ObjectId, lo devuelve el backend)
  - ID externo opcional: device_id al crear (UUID de nilo-node)

Crear sesion:

  POST /api/v1/recordings
  Authorization: Bearer ...
  Content-Type: application/json

  Body ejemplo:
  {
    "patient_id": "675abc...",
    "device_id": "nilo-node-session-uuid-1234",
    "archive_chunk_seconds": 300,
    "hls_segment_seconds": 6
  }

  Guardar el id devuelto como recording_id.

Cerrar sesion:

  POST /api/v1/recordings/{recording_id}/end
  Authorization: Bearer ...


================================================================================
PATRON DE SUBIDA CON PRESIGNED URL (video, audio, landmarks, pain)
================================================================================

  1. POST metadatos al backend -> recibe upload_url + id del recurso
  2. PUT binario a upload_url (directo a MinIO, SIN Bearer)
  3. POST .../confirm -> backend verifica objeto en MinIO

Las upload_url deben apuntar al host publico de MinIO (ej. 192.168.1.43:9002).
El backend usa MINIO_PUBLIC_ENDPOINT para generarlas.


================================================================================
VIDEO - SEGMENTOS / CHUNKS
================================================================================

Solicitar subida:

  POST /api/v1/recordings/{recording_id}/segments
  Authorization: Bearer ...
  Content-Type: application/json

  Body ejemplo:
  {
    "seq": 0,
    "kind": "archive",
    "fmt": "fmp4",
    "start_ts": "2026-09-17T10:30:00Z",
    "end_ts": "2026-09-17T10:35:00Z",
    "duration_seconds": 300.0,
    "codec": "h264",
    "width": 1920,
    "height": 1080,
    "fps": 25.0,
    "file_extension": "mp4"
  }

  kind: "live" (HLS corto) | "archive" (chunk largo)
  fmt: "fmp4" | "mp4" | "hls_ts" | "hls_fmp4"

  Respuesta:
    segment.id  -> segment_id para confirm
    upload.upload_url  -> URL para PUT
    upload.expires_in  -> segundos (default 3600)

Subir binario:

  PUT {upload_url}
  Content-Type: video/mp4  (o application/octet-stream)
  Body: bytes del fichero

Confirmar:

  POST /api/v1/recordings/segments/{segment_id}/confirm
  Authorization: Bearer ...

  Status del segmento pasa a "uploaded".

  Content-Type: application/json

  Body ejemplo:

    "video_segment_id": "675seg...",

  }

  source: "mediapipe" | "yolo" | "other"

  Respuesta incluye: id, upload_url, upload_expires_in

  PUT {upload_url}  -> JSON con keypoints
  POST /api/v1/landmarks/{landmarks_id}/confirm

================================================================================
PARAMETROS FISIOLOGICOS (sin MinIO)
================================================================================

Lectura individual:

  POST /api/v1/physiological
  Authorization: Bearer ...
  Content-Type: application/json

  Body ejemplo:
  {
    "patient_id": "675abc...",
    "timestamp": "2026-09-17T10:30:05Z",
    "device_id": "monitor-001",
    "metrics": {
      "heart_rate": 72,
      "spo2": 98,
      "systolic_bp": 120,
      "diastolic_bp": 80
    },
    "units": {
      "heart_rate": "bpm",
      "spo2": "%",
      "systolic_bp": "mmHg",
      "diastolic_bp": "mmHg"
    }
  }

  metrics es un dict libre (esquema flexible segun monitor).

Bulk (recomendado para rafagas):

  POST /api/v1/physiological/bulk
  Authorization: Bearer ...
  Content-Type: application/json

  Body: array de objetos PhysiologicalCreate
  [ { ... }, { ... } ]

================================================================================
MODO TEST (X segundos)
================================================================================

  1. login()
  2. patient_id = GET /patients?node_id=NODE_ID -> primer resultado.id
  3. rec = POST /recordings con patient_id y device_id=uuid sesion
  4. deadline = now + X_segundos
  5. seq = 0
  6. while now < deadline:
       - POST /physiological con vitales
       - POST /recordings/{rec.id}/segments
       - PUT upload_url con video
       - POST /recordings/segments/{segment_id}/confirm
       - (opcional) landmarks y audio en paralelo
       - seq += 1
  7. POST /recordings/{rec.id}/end

================================================================================
ERRORES HABITUALES
================================================================================

401 - Token expirado. Renovar con POST /auth/refresh.

403 - Usuario no es clinician ni root.

404 - patient_id, recording_id u otro ID invalido.

409 en confirm - El PUT a MinIO no se completo o la URL expiro.

Network error en PUT - La upload_url apuntaba a minio:9000 (host interno).
  El backend debe tener MINIO_PUBLIC_ENDPOINT=192.168.1.43:9002.


================================================================================
VERIFICACION RAPIDA DESDE NILO-NODE (bash)
================================================================================

  API=http://192.168.1.43:8001/api/v1
  NODE_ID=<tu node id>
  PATIENT_ID=<tu patient id>

  TOKEN=$(curl -s -X POST "$API/auth/login" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -d "username=clinician@niloai.net&password=clinician" \
    | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

  curl -s -H "Authorization: Bearer $TOKEN" \
    "$API/patients?node_id=$NODE_ID"

  curl -s -X POST -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"patient_id\":\"$PATIENT_ID\",\"device_id\":\"test-001\"}" \
    "$API/recordings"

  curl -s -X POST -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"patient_id\":\"$PATIENT_ID\",\"timestamp\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\",\"metrics\":{\"heart_rate\":70},\"units\":{\"heart_rate\":\"bpm\"}}" \
    "$API/physiological"
