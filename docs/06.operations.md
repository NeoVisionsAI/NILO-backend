# Copias de seguridad y monitorización operativa

## Health (`GET /health`)

Devuelve estado agregado JSON:

| Campo | Significado |
|-------|-------------|
| `status` | `ok` · `degraded` (disco ≥ umbral warn) · `critical` (Mongo/MinIO caídos o disco ≥ umbral crítico) |
| `ready` | `true` si Mongo y MinIO responden |
| `mongodb` / `minio` | Latencia y detalle |
| `disk` | Uso por ruta (`DISK_CHECK_PATHS` en config.yaml) |
| `disk_status` | Peor nivel entre rutas: `ok` · `warn` · `critical` |

- **HTTP 503** solo si `ready` es false (dependencias caídas).
- **Disco lleno**: `status`/`disk_status` pasan a `warn` o `critical` con HTTP 200 para que puedas alertar sin reiniciar el contenedor por disco.

Proceso vivo sin dependencias: `GET /health/live`.

Umbrales en `config.yaml`: `DISK_WARN_USED_PERCENT` (85), `DISK_CRITICAL_USED_PERCENT` (95).

En Docker, la API monta los volúmenes `minio_data` y `mongo_data` en `/var/minio-data` y `/var/mongo-data` para medir espacio real de datos.

## Copias de seguridad nocturnas

Cada ejecución guarda en `BACKUP_DIR/YYYY-MM-DD/` (UTC):

1. **MongoDB** (`mongo/`): volcado completo de la BD `nilo` (sesiones, vitales, metadatos de segmentos de vídeo, usuarios, etc.). Los binarios de vídeo **no** están en Mongo.
2. **MinIO** (`minio/`): objetos del **día UTC** cuya clave **no** está en categoría `video` (audio, landmarks, pain, …).

Retención: `BACKUP_RETENTION_DAYS` (default 14).

### Instalación del timer

Incluido en `./deploy.sh` (o manual):

```bash
sudo ./scripts/install-backup-timer.sh
sudo systemctl list-timers nilo-backup.timer
```

Backup manual:

```bash
./scripts/backup-nightly.sh
./scripts/backup-nightly.sh --date 2026-09-25
```

Desactivar en deploy: `NILO_BACKUP=0 ./deploy.sh`.

### Restauración (orientativa)

Mongo:

```bash
docker compose exec -T mongo mongorestore --username=admin --password=... \
  --authenticationDatabase=admin --db=nilo --drop /ruta/al/dump/nilo
```

MinIO: copiar ficheros de vuelta al bucket con `mc cp` o la consola.
