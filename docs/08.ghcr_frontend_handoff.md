# Handoff: publicar frontend en GHCR (mismo patrón que NILO-backend)

Copia este documento al agente del repositorio frontend.

Referencia implementada en backend: NeoVisionsAI/NILO-backend
- .github/workflows/publish-ghcr.yml
- deploy/vm-ghcr/ (compose.yaml, deploy.sh, bootstrap.sh, credentials.env.example, systemd opcional)
- docs/07.ghcr_deploy.md

---

## Objetivo

Publicar el frontend como imagen Docker en GitHub Container Registry (ghcr.io) en cada push a main/master.

Desplegar en servidores o VM con docker pull + compose, sin clonar el repo ni tener el codigo fuente en disco (solo scripts minimos de despliegue).

---

## 1. Imagen Docker

Anadir Dockerfile en la raiz del frontend.

Patron tipico: build estatico (npm run build / pnpm build) y servir dist/ con nginx o node.

La imagen NO debe incluir secretos. Variables publicas de build si aplica (VITE_API_URL, NEXT_PUBLIC_*, etc.).

Exponer el puerto del servidor web (ej. 80 o 8080).

---

## 2. GitHub Actions — publish-ghcr.yml

Crear .github/workflows/publish-ghcr.yml (nombre workflow ej. "Publish frontend image (GHCR)").

Triggers:
- push a ramas main y master
- push de tags v*
- workflow_dispatch (manual)

Permisos del job: contents read, packages write.

Pasos:
- checkout
- docker/login-action a ghcr.io con GITHUB_TOKEN
- docker/metadata-action: imagen ghcr.io/GITHUB_REPOSITORY_OWNER/nilo-frontend (ajustar nombre)
- tags: rama, sha corto, latest solo en rama por defecto
- docker/build-push-action: context ., push true

Opcional: subir artefacto deploy/vm-ghcr/ como nilo-frontend-vm-ghcr-deploy (upload-artifact).

Owner en GHCR va en minusculas (NeoVisionsAI -> neovisionsai).

---

## 3. Carpeta deploy/vm-ghcr/ (bundle sin codigo en produccion)

Crear la misma estructura que en el backend:

- compose.yaml — image: ${FRONTEND_IMAGE:-ghcr.io/OWNER/nilo-frontend:latest}, ports, env_file
- credentials.env.example — URL API backend, variables no secretas
- deploy.sh — docker compose pull + up -d; --install-systemd, --foreground
- bootstrap.sh — descarga solo ficheros de deploy/vm-ghcr via raw.githubusercontent.com (repo publico)
- run.sh — exec deploy.sh
- nilo-frontend-vm.service (o nombre coherente) — systemd en el host
- README.md — flujo operativo

Regla operativa:
- Cambio de CODIGO del frontend: en el servidor solo ./deploy.sh (pull imagen). No bootstrap, no zip, no git.
- Cambio de scripts de despliegue (compose, deploy.sh): ./bootstrap.sh en el servidor (raro).

---

## 4. Visibilidad del paquete GHCR

Repo GitHub publico NO implica paquete GHCR publico.

Tras el primer workflow exitoso:
GitHub -> Packages -> nilo-frontend -> Package settings -> Change visibility -> Public

O mantener privado y en cada VM:
echo PAT | docker login ghcr.io -u USUARIO --password-stdin
(PAT con read:packages)

Sin login, docker pull devuelve: unauthorized

---

## 5. Flujo desarrollo -> produccion

DESARROLLO (cada release):
1. commit + push a main
2. Esperar Actions "Publish frontend image (GHCR)" en verde

SERVIDOR — primera vez (Ubuntu, sin Docker):
sudo apt update && sudo apt install -y docker.io docker-compose-plugin curl
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
(cerrar sesion SSH y volver a entrar)

mkdir -p ~/nilo-frontend && cd ~/nilo-frontend
curl -fsSL https://raw.githubusercontent.com/OWNER/REPO/main/deploy/vm-ghcr/bootstrap.sh | bash
cp credentials.env.example credentials.env
(editar credentials.env — URL API, etc.)
docker login ghcr.io   # si paquete privado
chmod +x deploy.sh
./deploy.sh
opcional: sudo ./deploy.sh --install-systemd

SERVIDOR — cada actualizacion de codigo:
cd ~/nilo-frontend
./deploy.sh

Comando equivalente manual:
docker pull ghcr.io/neovisionsai/nilo-frontend:latest

---

## 6. Integracion con backend NILO

Documentar URL del API (ej. http://IP_VM:8001 o dominio).

Frontend build-time: inyectar URL API segun stack (Vite env, etc.).

Backend: CORS_ORIGINS debe incluir el origen del frontend (puerto/host donde sirve la imagen).

## 8. Referencia backend (comandos reales)

En VM backend:
cd ~/nilo-api && ./deploy.sh

Sustituir OWNER, REPO y nilo-frontend por los valores del repositorio frontend real.
