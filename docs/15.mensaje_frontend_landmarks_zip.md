# Mensaje para agente NILO-frontend — landmarks MediaPipe en ZIP

Copia al chat de **NILO-frontend**.

---

## Objetivo

Capturas faciales MediaPipe (panel DEV / episodios 1–2 min, ~478 puntos × N frames):

1. El **front** serializa el payload clínico (JSON).
2. Comprime en **un archivo ZIP** con un único `.json` dentro (p. ej. `landmarks.json`).
3. **`POST /api/v1/landmarks/upload`** (multipart) — **un solo request** autenticado.
4. El **backend** abre el ZIP, extrae el JSON, lo guarda en **MinIO** como JSON plano y registra `BodyLandmarks` en Mongo.

**No** PUT directo a MinIO (evita Mixed Content en `https://nilomed.eu`).

---

## Contrato JSON (MinIO y Mongo)

Incluir en el JSON (como ya usáis):

```json
{
  "schema": "nilo-mediapipe-face-capture-v1",
  "landmark_encoding": "flat-xyz",
  "frames": [ … ]
}
```

Tras el upload, en MinIO solo queda el **JSON descomprimido** (object key `…/landmarks_*_mediapipe.json`).

---

## ZIP en el navegador

Dentro del zip **exactamente un fichero `.json`** (nombre recomendado: `landmarks.json`).

Opciones de librería:

- **`fflate`** (`zipSync`) — ligero, buen encaje con Vite.
- **`JSZip`** — habitual en proyectos web.

Ejemplo orientativo:

```typescript
import { zipSync, strToU8 } from 'fflate'

async function buildLandmarksZip(payload: object): Promise<Blob> {
  const json = JSON.stringify(payload)
  const zipped = zipSync({ 'landmarks.json': strToU8(json) })
  return new Blob([zipped], { type: 'application/zip' })
}
```

Subida:

```typescript
const form = new FormData()
form.append('session_id', sessionId)
form.append('patient_id', patientId)
form.append('start_ts', startIso)
form.append('source', 'mediapipe')
form.append('capture_kind', 'face')  // 'pose' solo para tracking corporal
form.append('frame_count', String(frameCount))
if (endTs) form.append('end_ts', endTs)
const zip = await buildLandmarksZip(capturePayload)
form.append('file', zip, 'landmarks.zip')
return api.postFormData<LandmarksRecord>('/landmarks/upload', form)
```

`file_extension` en el form puede omitirse o quedar `json` (el servidor guarda `.json` en MinIO).

---

## `api.ts`

No forzar `Content-Type: application/json` cuando `body` es `FormData` (boundary multipart). Ver `docs/13.mensaje_agente_frontend_minio_upload.md`.

---

## Errores habituales

| Código | Causa |
|--------|--------|
| **413** | nginx `client_max_body_size` (subir a **64m** en `location ^~ /api/`). Ver `docs/14.nginx_api_upload_limits.md`. |
| **400** `Zip must contain at least one .json` | ZIP sin JSON o extensión incorrecta |
| **404** | Backend sin desplegar `POST /landmarks/upload` |

Límite backend: **64 MiB** de JSON **después** de descomprimir (`MAX_PROXY_UPLOAD_BYTES`). El ZIP en red suele ser mucho menor.

---

## Alternativas aceptadas por el backend

| `file` | Comportamiento |
|--------|----------------|
| `.zip` con un `.json` | **Preferido** (este mensaje) |
| `.json.gz` | gzip, guarda JSON en MinIO |
| `.json` plano | OK para pruebas pequeñas |

## Verificación

1. Subir desde nilomed.eu sin Mixed Content en consola.
2. Respuesta **201** con `id`, `object_key`, `status: processed`, `size_bytes`.
3. En MinIO: JSON bajo `patients/<pid>/sessions/<sid>/pose/<dd-mm-aaaa>/...`.

Prueba con curl (sustituir IDs y token):

```bash
zip -j /tmp/landmarks.zip /tmp/landmarks.json
curl -sS -X POST "https://nilomed.eu/api/v1/landmarks/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F "session_id=..." -F "patient_id=..." -F "start_ts=2026-11-24T12:00:00Z" \
  -F "source=mediapipe" -F "file=@/tmp/landmarks.zip;type=application/zip"
```
