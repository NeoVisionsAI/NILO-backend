# Mensaje frontend — visualizar MinIO (landmarks malla, audio, vídeo)

## Qué cambió en backend

1. **`GET …/{id}/download?expires_in=3600`** (default 1 h) devuelve JSON:

```json
{
  "bucket": "nilo-data",
  "object_key": "patients/…/landmarks_….json",
  "download_url": "https://…",
  "expires_in": 3600,
  "expires_at": "2026-11-26T12:00:00Z"
}
```

2. **`GET …/{id}/file`** — binario vía API (`Authorization: Bearer`), sin ir a MinIO. **Landmarks:** `/landmarks/{id}/file` (antes no existía; el front fallaba al usar `getBlob` en `/download`).

3. **`GET /storage/access?kind=landmarks&resource_id=…`** — mismo contrato para cualquier tipo (`audio`, `video_segment`, `pain_event`, `medical_document`).

## Flujo recomendado “Visualizar malla”

```typescript
const { download_url, expires_in, expires_at } = await api.get(
  `/landmarks/${id}/download?expires_in=3600`,
)
let blob: Blob
try {
  blob = await fetch(download_url).then((r) => r.blob())
} catch {
  blob = await api.getBlob(`/landmarks/${id}/file`)
}
// JSON en MinIO; si el zip era solo wire format, el objeto guardado es .json
const text = await blob.text()
const payload = JSON.parse(text)
```

Cachear en memoria `{ download_url, expires_at }` hasta `expires_at`; si el usuario repite antes, no hace falta llamar al API (o el API devuelve la misma URL).

## Infra producción

Si `fetch(download_url)` falla por host MinIO interno, priorizar **`/file`** o configurar `MINIO_PUBLIC_HOST` + nginx (`docs/10.minio_browser_uploads.md`).
