# MinIO: presignadas HTTPS desde el navegador (nilomed.eu)

Si el frontend va por **HTTPS** (`https://nilomed.eu`) y las `upload_url` salen como `http://192.168.x.x:9000/...`, el navegador bloquea el **PUT** por **Mixed Content**.

Los fisiológicos no pasan por MinIO; el problema afecta a **audio, vídeo, landmarks, dolor**, etc.

## Arquitectura típica

| Conexión | Configuración |
|----------|----------------|
| API (contenedor) → MinIO en LAN | `NILO_INFRA_HOST` + `MINIO_API_PORT` (ej. `192.168.122.1:9000`), `MINIO_SECURE=false` |
| Navegador / nilo-node → MinIO | `MINIO_PUBLIC_HOST` + `MINIO_PUBLIC_SECURE=true` (hostname **público** detrás de nginx) |

La API firma las URLs con el **endpoint público** (`MINIO_PUBLIC_*`), pero sigue hablando con MinIO por la red interna.

## Variables en `credentials.env` (VM API)

Ejemplo producción:

```env
NILO_INFRA_HOST=192.168.122.1
MINIO_API_PORT=9000

# Lo que debe ver el navegador (mismo host que el proxy TLS hacia MinIO)
MINIO_PUBLIC_HOST=minio.nilomed.eu
MINIO_PUBLIC_SECURE=true
# Puerto 443 implícito con MINIO_PUBLIC_SECURE=true; override opcional:
# MINIO_PUBLIC_PORT=443

# Override completo si ya incluyes puerto:
# MINIO_PUBLIC_ENDPOINT=minio.nilomed.eu

CORS_ORIGINS=https://nilomed.eu
```

Tras guardar: `./deploy.sh` o `docker compose up -d` y revisar logs de arranque:

```text
MinIO internal=192.168.122.1:9000 secure=False | presign=minio.nilomed.eu secure=True
```

## Nginx (host o frente al silo)

Subdominio recomendado (path-style S3 compatible con el SDK):

```nginx
server {
    listen 443 ssl;
    server_name minio.nilomed.eu;

    # certificados TLS …

    client_max_body_size 0;
    proxy_buffering off;
    proxy_request_buffering off;

    location / {
        proxy_pass http://192.168.122.1:9000;
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

El hostname en `MINIO_PUBLIC_HOST` debe coincidir con `server_name` y con el **Host** que usa el cliente al hacer PUT.

Opcional en el contenedor MinIO (`host_minio`):

```env
MINIO_SERVER_URL=https://minio.nilomed.eu
MINIO_BROWSER_REDIRECT_URL=https://minio.nilomed.eu
```

## CORS en el servidor MinIO

El API de NILO ya envía `CORS_ORIGINS` para FastAPI; **MinIO** necesita su propia política para que el navegador pueda hacer **PUT** cross-origin (o mismo sitio si usas subdominio).

Con `mc` en el host del silo:

```bash
mc alias set silo http://127.0.0.1:9000 "$MINIO_ACCESS_KEY" "$MINIO_SECRET_KEY"
mc admin config set silo api cors_allow_origin="https://nilomed.eu"
mc admin service restart silo
```

Varios orígenes: separados por comas. En Docker:

```text
MINIO_API_CORS_ALLOW_ORIGIN=https://nilomed.eu
```

## Comprobar

1. Login en nilomed.eu → panel de ingestión / audio.
2. `POST .../audio` (o vídeo) → en la respuesta, `upload.upload_url` debe empezar por `https://minio.nilomed.eu/` (o tu host público), **no** por `http://192.168...`.
3. El PUT desde el navegador debe devolver **200** (o 204).

Prueba manual del presign (tras login):

```bash
# Crear clip de audio de prueba y mirar upload_url en JSON
curl -sS -X POST "https://nilomed.eu/api/v1/audio" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"session_id":"...","patient_id":"...","kind":"voice_note","start_ts":"2026-03-25T12:00:00Z"}' \
  | python3 -m json.tool
```
