# Mensaje para agente NILO-frontend — transcripción notas de voz

Copia al chat de **NILO-frontend**.

---

## Objetivo

Cada **nota de voz** (`AudioRecording`, `kind: voice_note`) debe mostrar el **texto transcrito** asociado al audio, persistido en backend.

Backend: Whisper local (`faster-whisper`), ver `docs/20.audio_transcription.md`.

---

## Campos en API (`AudioOut`)

| Campo | Valores |
|-------|---------|
| `transcription` | `string \| null` — texto |
| `transcription_status` | `none` \| `pending` \| `done` \| `failed` |

Tras subir nota (`POST /audio/upload`), `transcription_status` suele ser **`pending`**.

---

## Flujo recomendado (UI)

1. **Subir** — `POST /api/v1/audio/upload` (multipart, `kind=voice_note`) → recibe `id`.
2. **Transcribir** — `POST /api/v1/audio/{audio_id}/transcribe`  
   - Staff JWT (`require_staff`).  
   - Body vacío o `application/x-www-form-urlencoded`.  
   - Opcional: `force=true` para re-transcribir; `language=es`.  
   - **Puede tardar 10–60 s** en CPU → spinner / “Transcribiendo…”.
3. **Respuesta** — `200` `AudioOut` con `transcription` y `transcription_status: done`.  
   Si falla el motor: `transcription_status: failed` (revisar texto vacío o reintentar).
4. **Listado / detalle** — `GET /audio?patient_id&session_id` o `GET /audio/{id}`; mostrar `transcription` bajo el reproductor o en tooltip.

No hace falta PUT a MinIO para transcribir: el API lee el objeto ya guardado.

---

## Ad-hoc (solo texto, sin guardar audio)

```http
POST /api/v1/audio/transcribe
multipart: file=<audio>, language=es (opcional)
→ { "text": "…", "language": "es" }
```

Útil para pruebas; el flujo clínico normal es **upload + transcribe por id**.

---

## Auto-transcripción (opcional, ops)

Si en servidor `AUTO_TRANSCRIBE_VOICE_NOTES=true`, tras upload el backend transcribe en **background**.  
UI: polling `GET /audio/{id}` cada pocos segundos hasta `done` o `failed` (o desactivar botón “Transcribir” si ya `pending`).

Por defecto está **off**; el front debe llamar **`POST …/transcribe`** explícitamente.

## Servicio front sugerido

En `audio-recording.service.ts`:

```typescript
transcribe(audioId: string, opts?: { force?: boolean; language?: string }): Promise<AudioRecording> {
  const body = new URLSearchParams()
  if (opts?.force) body.set('force', 'true')
  if (opts?.language) body.set('language', opts.language)
  return api.post<AudioRecording>(`/audio/${audioId}/transcribe`, body)
}
```

(UI existente de notas de voz / condata / Explorar: enganchar tras upload exitoso o botón “Generar transcripción”.)

---

## Errores

| HTTP | Acción UX |
|------|-----------|
| 503 | Transcripción deshabilitada en servidor |
| 422 | Audio vacío, sin voz, ffmpeg, etc. — mensaje genérico + `failed` si devuelve fila |
| 404 | Audio inexistente |

---

## Criterios de aceptación

- Tras grabar nota en sesión activa, el usuario puede obtener texto legible.
- Re-cargar paciente/sesión: el texto persiste en listado.
- Opcional: botón re-transcribir con `force=true`.
